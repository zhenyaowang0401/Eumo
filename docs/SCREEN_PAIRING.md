# 小鼹鼠外接屏：四位码配对与学习记录

目标是让小屏幕独立计时和挖掘，原网站 / 桌面 APP 接收它的深度、每日学习时间、每次学习记录和实际收获。网站原有功能和存档保留。小屏幕继续使用精简界面，不开放商店、换装或 Chat。

本次基于 Luca 的 `f75773092ad6f0460f4be6f3a81a045c8d072866` 合入，不用旧版网站覆盖新版。固件源代码在 `hardware/Eumo169/`，无需下载交接压缩包。

## 配对流程

1. 小屏幕连接能上网的 2.4 GHz Wi-Fi，等待时钟就绪。已有扫描网络、选择名称、输入密码的流程保留。
2. 小屏幕 `Setup → Pair screen → New code` 显示四位数字，有效期 5 分钟，开头的 0 也要输入。
3. 网页 Focus 主屏幕右上角点击「连接小屏幕」，输入四位码。它会提示一个 `Computer 1234` 形式的名称。
4. 小屏幕显示同一名称；点击 `Confirm pairing` 才授权读取。别人只猜中四位码不能读取学习记录。输错或配对被占用可点击 `Reject / new code` 重新生成。
5. 小屏幕开始、暂停或结束学习，网页自动跟随。网页本地计时暂时停用，避免同时记两份时间。
6. 日后自动恢复绑定。网站、桌面客户端和其他浏览器分别配对一次；每块设备最多 8 个读取端。无需与电脑处于同一 Wi-Fi，只需双方能访问互联网。

`END → End and save` 彻底结束本次学习，结算并保存时间、深度、材料和稀有收获，然后打开记录页。再次开始是新的一次。暂停仍保留当前会话，可以继续。回地面的箭头和拖动地道只改变浏览位置，不清空深度。

## Luca 的发布步骤

本地编译和测试不能代替发布。只有 GitHub 代码、Vercel API、Supabase 表和设备固件全部更新，线上配对才会工作。

1. 审查该功能分支，与 `main` 合并。保留 `api/dig-sync.js`、`api/dig-pair.js`、`device-progress.js`、`device-records.js`，以及主界面 / 桌面协议改动。
2. 在原 Supabase 项目的 SQL Editor **依次**执行 `database/dig_sync.sql`、`database/dig_pairing.sql`。两个脚本只添加设备同步表及函数；不覆盖原网站存档。使用了 RLS，仅服务器 service role 可访问。
3. 原 Vercel 项目配置服务器环境变量 `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY`，部署到 `https://1111-phi-ten.vercel.app`。不要把 service role key 放到 Arduino、浏览器、仓库或聊天里。
4. 检查 `/api/dig-pair`、`/api/dig-sync`：无凭据 POST 应返回 JSON 401，而非 404。实际配对不能出现 503。401 只表示路由存在，不能证明数据库已配置成功。
5. 设备按 `hardware/README.md` 编译更新；保留现有分区、NVS 和 FFat。已有设备不点 Initialize storage、不擦除 Flash。
6. 已安装的桌面 APP 需要用本分支重新构建并发布新版；更新网页不会自动改动旧安装包的界面。

此前的 `api/device.js` / `database/device_pairing.sql` 属于旧的朋友身份配对，与本流程不同。**四位挖掘配对不需要执行那个 SQL**，也不需要打开小屏幕 Chat。

## 与原网站相同的规则

规则源：`journey.js` 和 `treasures.js`。ESP32 使用相同算法的 C++ 实现；测试直接运行原 JavaScript 生成预期值，并对比设备实际结算。

| 机制 | 当前原网站与设备 |
| --- | --- |
| 正式 Study / Work 挖掘 | 每 30 秒 1 米 |
| 星币 | 累计合格时间每 5 分钟 1 星 |
| 发现机会 | 累计合格时间每 10 分钟一次 |
| 普通材料 | 新会话 `rewardVersion: 2`，每次发现机会 40%，材料种类沿用原哈希算法 |
| 稀有收藏 | 同一发现机会独立 3% 判定，原种子、原哈希、原 10 个物品 |
| 暂停 / 休息 | 不增加正式挖掘时间或奖励 |
| 旧会话 | 没有 `rewardVersion: 2` 的会话按旧规则完成，不重新计算旧收获 |

设备已有旧记录保持不变。新开始的会话采用最新版规则；网站只导入已经结算的结果，**不再抽一次奖**。实际概率不意味着每次学习必定获得材料。保留离线存档并在联网后补传。

## 存档与同步边界

- 单向：设备 → 各自配对的网页 / APP。本实现不是把几个原本独立的浏览器存档自动变成同一账号，也没有通过网页远程启动设备。
- 第一次配对会明确确认：把设备已有累计进度加入当前存档，之后只加新增量。比如网页 100 米，设备 140 米，配对后网页 240 米；设备再挖 5 米，网页 245 米。
- 深度、正式学习时间、每日记录跟随设备；材料、星币、稀有物品和逐次明细在设备结束并结算后导入。不会替换网页服装、布置或正在使用的工具。
- 设备身份稳定，重新生成短码不换设备身份。重复包、刷新、断开再连接不会重复奖励。同一存档的另一个标签页不能同时写入。
- 绑定及读取凭据保存在当前浏览器 / APP 本地。清除站点数据、换浏览器需要重新配对。不要删除存档中的 `deviceImports` 去重信息；从旧备份恢复时须核对设备进度是否已计入。
- 设备每约 5 秒上传，网页每约 3 秒读取。正常数秒后显示，断线超过约 20 秒停止播放挖掘。断网期间设备仍保存本地数据；云端收到后才算完成同步。
- 有明确容量上限：366 个日期、2000 条会话记录，设备请求最多约 900 KB。超过上限明确报错，绝不静默截断旧记录。长期正式发布前应改用分页增量日志。
- 旧私有观看链接保持兼容；`Revoke paired browsers` 撤销新四位码绑定，不撤销已发出的旧私有观看链接。

## 验收与测试

`npm run test:device` 验证真实 PostgreSQL SQL（PGlite）、API、四位码过期 / 确认 / 限流、导入去重、旧身份迁移、桌面 Bearer 转发及存档写入失败回滚。

`node tests/verify_device_browser.cjs` 使用独立临时 Chrome 资料目录，真实打开原网页，模拟设备 HTTP 响应。它验证 0372 配对等待实体确认、已有 100 米 + 设备 140 米、后续 +5 米、奖励仅入账一次、刷新、断线和恢复独立计时。它不是公网与实体设备联调。

`hardware/tests/run.cjs` 对比 848 组新旧原网站规则、真实设备数据格式、结束保存、重启恢复、屏幕触摸及 7 层地形的 12357 个绘制矩形。环境设置见硬件 README。

发布后必须用实体设备完成：配对 → 开始 → 暂停 → 结束 → 网页历史 / 材料更新 → 刷新不翻倍 → 断网挖掘 → 重新联网补传。此流程完成之前，不应把功能标为已经线上联调成功。
